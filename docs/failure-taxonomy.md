# Failure taxonomy

Stage5 Browser treats failures according to the layer that owns recovery. A generic retry is not a recovery strategy.

| Layer | Examples | Detection | Recovery owner | Default response |
| --- | --- | --- | --- | --- |
| MCP transport | host disconnect, malformed protocol output | transport close or protocol error | MCP host/server | close cleanly; never write non-protocol data to stdout |
| MCP build lifecycle | server artifact rebuilt after process start, compatible artifact drift, or stale tool catalog | runtime fingerprint plus versioned tool-catalog and worker-protocol metadata | MCP host and supervisor | roll a fingerprint-only compatible worker automatically; return `MCP_RESTART_REQUIRED` only for a changed public browser contract; keep already-loaded Lounge coordination available so agents can coordinate the reconnect without granting browser authority |
| Lounge store | SQLite contention, store worker failure, or inaccessible durable storage | bounded SQLite busy timeout, worker error/exit, and rejected worker-thread RPC | Lounge service | fail the coordination operation with a structured sanitized reason; keep it outside the browser queue and never claim delivery without a committed message |
| Lounge delivery | recipient is offline, a response is lost, or a sender retries | durable per-recipient delivery rows, monotonic seen/acted acknowledgements, presence leases, and sender idempotency keys | sending and receiving agents | retain at-least-once delivery until acknowledgement; deduplicate an identical retry; reject conflicting reuse; never interpret delivery as user authorization |
| Lounge wake lifecycle | a bounded wait expires, is cancelled, or the model task ends | explicit listening/processing/connected/offline presence plus the wait result | receiving agent and MCP host | renew immediately after timeout or processing while collaboration remains active; queue backlog for the next join when the task has ended; never label a merely connected agent wakeable |
| Lounge pinned notice | concurrent manager edits, a transport retry, or a listener waiting on stale guidance | compare-and-set revision, manager allowlist, and sender-scoped idempotency key | trusted manager and Lounge store | reject stale or unauthorized writes; deduplicate an identical retry; wake listeners on the new revision without manufacturing message delivery |
| Lounge manager history | manager needs a message not addressed to it, or an ordinary member attempts room-wide access | trusted local manager allowlist, joined room identity, bounded sequence cursors, and metadata-only audit row | Lounge store | return bounded room-scoped history without claiming delivery; reject unconfigured members; never treat history as new user authority |
| Supervisor | queue corruption, worker startup failure | failed readiness handshake | supervisor | reject with a structured terminal error |
| MCP/worker protocol | stale MCP starts a worker with a different command contract | versioned initialization handshake; fingerprints remain diagnostic identity only | MCP host | reject a real protocol mismatch with `MCP_RESTART_REQUIRED`; never reject solely because exact builds differ |
| MCP terminal delivery | a worker result or timeout is created but the caller does not receive it promptly | reserved operation ID plus worker-request, worker-result, terminal, persistence, and response-created timestamps | MCP host and caller | return within the supervisor deadline; recover the in-memory terminal result through `browser_operation_status`; never replay the browser command merely because caller delivery is uncertain |
| Worker process | deadlock, event-loop stall, crash | hard deadline, process exit, IPC disconnect | supervisor | terminate the process group and spawn a clean worker |
| Browser ownership | live controller, another live Stage5 session, conclusively proven orphan, abandoned record, malformed record, or external lock owner | atomic per-profile lease containing exact worker/browser start identities, executable fingerprint, control mode, release phase, and heartbeat, corroborated by active OS locks | worker | reattach or terminate only a fingerprint-matched non-private Stage5 orphan; never overwrite an invalid lease, delete browser locks, or signal an unknown process |
| Browser process | crash, orphan, profile lock, or a prior owned process still releasing its singleton | Playwright disconnect, failed launch, durable lease state, explicit active profile-lock state, and a bounded release wait | supervisor and worker | close or kill only the proven owned process tree; expose exact owner/recovery evidence and relaunch only when the profile is actually available |
| Browser context | unexpected close, unusable persistent context | context close event or operation error | worker | recreate the context; preserve only the dedicated profile |
| Agent context continuity | MCP-host reconnect resets a Chrome/Brave/etc. agent to the configured default, or several agents use different backends concurrently | stable Lounge identity plus hashed privacy-minimized backend/review-policy context | MCP host context manager | restore only that agent's backend/policy before the next browser operation; never use one global last-browser value or persist URLs/pages/values; on first migration require one explicit uniquely proven backend start |
| Page/renderer | page crash, closed target, unresponsive renderer | page events or failed health probe | worker | discard the page and create a new one; escalate to worker restart if needed |
| Page document continuity | a main document reloads, closes, or changes during a native worker detach gap | performance time-origin while attached plus private opaque target/loader continuity across exact native reattachment | worker and caller | durably emit `all_unsaved_form_state_may_be_lost` before further work; fail if the exact selected target disappeared; re-observe the entire form and never infer values from prior controller state |
| Navigation lifecycle | commit succeeds but readiness stalls, client redirect follows, or HTTP response is non-2xx | URL commit, bounded readiness/stabilization, redirect observation, and response status | worker and caller | return committed state plus structured warning/redirect evidence instead of declaring workflow success |
| Frame lifecycle | observed frame detaches or belongs to an old tab | opaque frame-ID lookup plus attachment check | caller | return `TARGET_NOT_FOUND`; inventory frames again before retrying |
| Private interaction lifecycle | controlled browser still releasing, native browser still running, profile locks remain, or the current process exit is abnormal/unavailable | retained `close_requested → process_exited → profile_unlocked` phase, exact native-process identity and exit code/signal, active OS lock ownership, advisory Chromium marker value/mtime comparison, and effective evidence source | user and worker | continue an interrupted phase instead of relaunching; never force-close or edit profile state; accept zero exit/no signal/zero active locks, or offer one deliberate unlocked-profile override without repeating private input |
| Authentication launch identity | native and controlled executable, backend, user-data root, or profile partition differ | configured binding plus the canonical Profile Path observed from the running Chromium instance | worker | return `AUTH_NOT_PERSISTED`; do not ask the user to repeat login in an untrusted window |
| Authentication storage continuity | target-origin cookie-key presence changes across native exit, controlled start, or target load, or a non-root post-login route is not reached | offline database metadata, live context metadata reduced to non-value key facts, non-exported hashes, restored-target flag, webdriver observation, authentication-route postcondition, and bounded preview | worker and caller | return `AUTH_NOT_PERSISTED` for verified loss; do not classify an otherwise exact origin/path/fragment as lost solely because the site appended query metadata when the caller expected no query; explicit expected queries remain strict; retain the controlled page, report `lossBoundary` and non-causal `automationCorrelation`, and do not replay login. Never infer live absence from open SQLite |
| Authentication boundary evidence | exact human clicks and native-window requests are not instrumented, or storage survives while the site still renders signed out | sanitized before/after route and keyed semantic fingerprints plus bounded semantic preview | caller | treat storage and boundary comparisons as evidence only; stop on signed-out controls and require a fresh full snapshot to prove signed-in state |
| Modal inspection | portal controls exceed document snapshot depth, or several dialogs compete | unique visible-modal root and ambiguity count | worker and caller | preserve one ref map for the unique modal; otherwise warn and inspect the document without choosing a modal |
| Control workflow | a native/custom select is closed, virtualized, multi-select, already selected, or another popup is open | exact control/popup/option capabilities, structural popup ownership, bounded exact-surface scrolling, selected-state reconciliation, and per-step workflow evidence | form manager and agent | let the agent choose meaning from bounded observed options; dismiss at most one exactly owned competing popup with its own close proof; refresh capabilities between physical multi-select inputs; never toggle an already-selected option or replay an unconfirmed step |
| Control-inspection document transition | revealing or preparing a custom control crosses an authentication redirect, reload, or replacement document | original document version, combined opener/preparation dispatch evidence, durable sanitized page events, and fresh tabs | form and lifecycle managers | abort the inspection as `document_changed_during_control_inspection`; let that lifecycle classification supersede an inner selected-state postcondition, read page events, treat unsaved state as possibly lost when `document_replaced` is present, and never replay possible input |
| JavaScript dialog | an alert, confirm, prompt, or beforeunload blocks the browser after possible input | one action-scoped expected type/response and sanitized durable dialog observation | dialog manager and caller | accept/dismiss only the exact expectation; dismiss unexpected dialogs to prevent deadlock but fail the action closed; never retain message or prompt text and never replay the trigger |
| Element targeting | missing, transitioning, or ambiguous role/name | bounded one-second zero-match wait followed by locator count and actionability checks | caller | return candidates/error; never click an arbitrary first match; a final zero match reports false dispatch explicitly so earlier/autonomous UI changes are not attributed to it |
| Snapshot reference lifecycle | ref is stale, reused, absent, from another document/frame, or replaced during necessary pre-input activation; an unnamed link's decorative DOM text disagrees with its accessibility name | latest snapshot ID, document version, observed-ref membership, retained modal/document scope, Playwright-captured role/name, and the snapshot-observed direct destination when present | caller and worker | after activation bind the original ref or one unique exact role/name-equivalent target inside the retained scope while dispatch is false, requiring the same direct link destination; otherwise return `TARGET_NOT_FOUND`/`AMBIGUOUS_TARGET`; consume the capability and take a fresh snapshot |
| Dormant popup rendering | a closed selector keeps CSS-visible options, stale status content, or an inner scroller in an offscreen portal | exact popup refs plus clipped viewport intersection through overflow ancestors | worker and caller | remove inactive popup option/surface subtrees and their offscreen scroll capabilities from snapshots; require onscreen clipped visibility for popup `expectedVisible`; preserve ordinary offscreen page refs and never replay a dispatched opener after a failed rendered-state postcondition |
| Local file preflight | path is relative, missing, unreadable, a symlink/directory, or exceeds the input's multiplicity | filesystem metadata plus the observed file-input constraints; file contents are never read | caller | return `INVALID_FILE` or a structured pre-dispatch failure without consuming an otherwise valid capability |
| File-selection outcome | the input accepts the action but matching privacy-minimized file metadata is absent both during capture-phase input/change handling and from the retained `FileList`, or the command fails after dispatch may have begun | exact observed element handle plus event-time and post-dispatch name/size/count comparison | caller | return `POSTCONDITION_FAILED` or outcome-unknown evidence; inspect the composer and never replay without a fresh snapshot proving no attachment exists |
| Upload processing | selection is confirmed but progress, service completion, or error state is unclear | semantic progress controls, optional caller-supplied completion/error markers, fresh preview, and temporally bounded network counts | caller and service adapter | report `completion_observed`, `in_progress`, `error_observed`, or `unverified`; never equate file selection or HTTP success with upload completion |
| Download capture | an action may start a download but completion, artifact persistence, or caller delivery is unclear | action-scoped expected-download cursor plus durable private randomized artifact manifest | transfer manager and caller | reconcile the trigger once, wait/read by sequence without replay, expose only bounded artifact metadata, and classify interrupted or failed capture truthfully |
| Active-page and native-window drift | an auxiliary popup appears, the selected page closes, the context briefly reports no visible page, or a controller-selected Chromium target remains hidden/minimized at the OS window layer | explicit controller selection, opaque native target continuity, live-page membership, unique handoff visibility, sole-page fallback, renderer-first visibility observation, exact CDP target-window resolution only when hidden, exact-process hidden/frontmost observations, explicit unhide/all-window activation, one exact-PID Process Manager fallback when AppKit leaves an unhidden process non-frontmost, and final renderer visibility | worker | keep already-visible pages background-safe; preserve the exact selected native target across worker replacement; on macOS restore only its exact minimized Chromium window and activate only the verified Stage5-owned PID when renderer visibility requires it; fail closed with `page_not_active` if the renderer remains hidden |
| Click outcome | full or partial exact-target input occurs and the URL/selection/visible/hidden postcondition may have changed | shared absolute deadline plus bounded postcondition reconciliation inside the evidence-finalization reserve; exact hidden checks accept zero semantic matches or one uniquely hidden match, keep ambiguity/frame loss/observation failure unknown, and omit the semantic name from results | caller | return normal success when the requested effect is observed while preserving truthful partial dispatch evidence; otherwise return `POSTCONDITION_FAILED` for confirmed clicks or the original non-retriable partial-input failure; never equate hidden-state proof with a persisted value or downstream submission |
| Compatible update state | a completed build appears while an unsaved form or duplicate same-URL tabs are open, or a replacement worker would erase the preceding action's terminal evidence | direct-Playwright versus proven native-CDP boundary, connected-state tracking, private opaque target/document identities, sanitized URL, and bounded last-action diagnostic | supervisor and worker | defer direct-Playwright replacement until explicit stop; reattach native-CDP in place to the exact selected target; retain evidence during graceful shutdown and restore it only for the same target/document/URL; never reconstruct a connected page from only its last URL or alter the terminal result |
| Unnamed editor fill | an active textbox/contenteditable has no accessible name, its retained snapshot/modal scope changes, or a reactive editor never satisfies Playwright's stability-gated scroll despite already being visible | latest snapshot ID/ref, frame/document version, exact snapshot-captured scope/editor handles, retained-scope containment, exact preparation substep, pre-scroll and final target state, bounded fill phase, and privacy-safe input/change/logical-value-match booleans | worker | inspect the retained handle first; skip movement when it is visible and in view, otherwise use one bounded exact-handle DOM scroll and revalidate; never re-resolve the ref or rescan modal scope; consume the capability on every attempt; never invent a name, expose the value, or replay partial input |
| Click actionability and dispatch | target is hidden, disabled, out of viewport, detached, virtualized, covered, continuously unstable, changes during necessary page activation or later validation, a React popup opener replaces itself during input, navigation replaces its document, or both exact-handle transports emit no event | one role/ref engine; background-safe page activation before final target binding; bounded incremental scrolling; exact-node retention; one pre-input unique role re-resolution after activation/scrolling; one retained-scope exact role/name ref rebind after activation; unique same-article ref rebind; one pre-input-selected native-button key (Enter by default, Space for explicit expected-visible menu/list options); revalidated target state; selected-page activation immediately before input; in-document and externally retained trusted key/pointer/mouse/click booleans; reserved evidence-finalization time before the supervisor deadline | caller | return clicked, definitely not dispatched, or ambiguous evidence; consume refs; reject missing/ambiguous replacements; never change keys or transports after keyboard input or partial pointer input; use guarded pointer fallbacks only after zero trusted pointer events and unchanged actionability; never expose coordinates or replay partial/ambiguous dispatch |
| Consequential ambiguity | click or submission times out after it may have fired | timeout after dispatch | caller and service adapter | do not retry; verify authoritative external state first |
| Workflow review policy | an agent needs a fill-only/local-validation boundary without encoding site meanings in browser core | deterministic command class plus explicit agent-declared intent | policy manager and agent | block the declared consequential class before dispatch in `review_only`; never infer submit, terms, communication, persistence, or financial meaning from labels, URLs, selectors, or regexes; the policy never expands user authority |
| Screenshot artifact | selected tab is not foreground, GPU rendering is unsettled, the PNG is unusually uniform, or the MCP client's managed image view misrenders a valid source artifact | immediate page activation, semantic-content boolean, PNG byte density, one bounded recapture, and retained private source path | worker and caller | fail closed when the selected page cannot activate; recapture one suspicious artifact; report evidence without pixels/page text; inspect the source path before declaring a contentful artifact black |
| Dynamic-feed boundary | viewport reaches the current bottom after prior content growth, but no explicit feed-end marker is visible | per-step geometry/content-growth history plus an optional semantic end marker | caller | report `dynamic_content_stalled` or `geometric_boundary_unconfirmed`; do not claim the timeline is complete |
| Nested scroll ownership | document scrolling is unchanged while one or more inner vertical or horizontal surfaces can scroll | bounded snapshot inventory, opaque document-bound container refs, and exact retained element handles | caller and worker | expose candidates; require an exact fresh target capability; never guess a selector or silently choose a container |
| Feed loading stall | substantive articles do not grow, relevant visible loading indicators do not disappear, React replaces the pinned observation root, or a bounded semantic scan cannot cover the selected surface | visible-renderer activation before baseline/each step, one exact pinned observation root, loading-only status shells separated from substantive articles, complete aggregate before/after counts, plus scroll-correlated sanitized network events | caller and worker | fail closed as `page_not_active` before hidden-renderer movement; return prompt `scroll_observation_surface_unavailable` with completed-step facts after root replacement or `scroll_observation_incomplete` when candidate limits are exhausted; never replay completed steps or infer from truncated counts; ignore unrelated offscreen/out-of-surface loaders; otherwise report a genuine scoped timeout and `dynamic_content_stalled` at the current boundary; never claim completeness |
| Fractional scroll boundary | the browser reports a position fractionally below an integral maximum, such as `2443.5 / 2444` | CSS-pixel geometry with a one-pixel boundary tolerance | worker | recognize the current geometric boundary while keeping semantic feed completion unconfirmed |
| Authentication/site policy | CAPTCHA, expired login, bot rejection, or a KYC/private-input screen | explicit private bootstrap, fresh post-resume page state, and service response | user or service adapter | hand only the exact private screen to the user, keep passwords/passkeys/OTPs/EINs/identity documents/selfies outside agent messages and logs, follow the backend-specific leave-open/normal-close instruction, resume, then verify with a fresh snapshot; or use an official API/CLI |

`browser_recover` recovers the worker boundary only. Its terminal result explicitly reports either `worker_recovered_browser_running` or `worker_recovered_browser_stopped`; neither outcome claims that an MCP tool catalog was reloaded.

For bot-sensitive authentication or KYC, use Brave, Chrome, or Edge. The pinned Playwright Firefox runtime currently reports `navigator.webdriver: true` even during its uncontrolled native handoff, so Firefox's private-input lifecycle support does not imply automation invisibility.

## Recovery invariants

- Read-only operations may be retried only after the failed layer has been reset.
- Consequential operations are never retried merely because their response timed out.
- Killing a worker must kill the browser descendants it owns.
- Recovery never attaches to or modifies the user's default Chrome profile.
- Recovery never kills a human authentication browser, removes its profile locks, or rewrites browser shutdown preferences.
- Every operation ends as `succeeded`, `failed`, or `timed_out`; there is no permanently pending state.
- Evidence identifies the failed layer without recording page contents or sensitive inputs.
