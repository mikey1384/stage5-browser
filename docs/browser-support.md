# Browser support

Stage5 Browser exposes one semantic automation surface across multiple isolated browser backends. An agent chooses a named backend; it never supplies an executable path or attaches to a person's everyday profile.

| Selection | Engine | Runtime source | Isolated profile |
| --- | --- | --- | --- |
| `chromium` | Chromium | Pinned Playwright runtime | `profiles/default` |
| `chrome` | Chromium | Discovered Google Chrome installation | `profiles/chrome` |
| `brave` | Chromium | Discovered Brave installation | `profiles/brave` |
| `edge` | Chromium | Discovered Microsoft Edge installation | `profiles/edge` |
| `firefox` | Firefox | Pinned Playwright runtime | `profiles/firefox` |
| `webkit` | WebKit | Pinned Playwright runtime | `profiles/webkit` |

The installed Safari application is not the same runtime as Playwright WebKit. Supporting Safari itself requires a separate WebDriver adapter and user-enabled Safari Remote Automation; Stage5 Browser does not claim that support yet. Other Chromium brands can be used only through a trusted operator-supplied `STAGE5_BROWSER_EXECUTABLE_PATH`, never through an agent argument.

## Agent workflow

For any workflow that depends on a particular browser or authenticated profile:

1. Call `browser_available`.
2. Read `profileState`, `startable`, and `recoverable`; `installed: true` alone is insufficient. `owned_active` means this session already controls the backend, `busy_other_stage5_session` means another live Stage5 owner must finish or stop it, `owned_orphaned` is recoverable only through the exact recorded lease, and `external_owner` must not be retried, killed, or lock-deleted. Do not guess or silently fall back.
3. Call `browser_status`. Read controller state, lock state, and `profileOwner.lease` together. Every launch records a private atomic lease with exact worker/browser start identities, executable fingerprint, control mode, phase, and heartbeat. `state: "stopped"` therefore does not imply a free profile. If no owner exists and the backend is startable, call `browser_start`; if the lease proves a non-private Stage5 orphan, one `browser_start` will safely reattach or terminate/relaunch only that exact owner. If a different backend is already controlled, call the explicitly destructive `browser_switch`, which preflights before closing current tabs. Never delete browser lock files or signal an unverified process.
4. Call `browser_status` again and verify the returned `browser` matches the request.
5. Call `browser_auth_status` when the workflow requires an account or another private step. Explicitly select the intended backend, then call `browser_request_login_handoff` with the exact page requiring a password, passkey, CAPTCHA, OTP, EIN, identity document, selfie, or other private input. It retains `close_requested → process_exited → profile_unlocked`, then launches the same executable/profile binding as a private native browser. If the request returns `releasing_control`, call that same request again to continue the retained phase; do not reopen the browser or repeat the private step. Match the application name and short label to the static Stage5 marker tab. While `awaiting_user`, do not call browser-control or recovery tools. The user completes the private step without sending its value or document to the agent, then follows the returned instruction: leave Chromium-family browsers open for same-process attachment, or quit Firefox normally for restart-based resume. Call `browser_resume_after_login` with a non-root post-login URL if one is stable, or no URL expectation. With exact authentication matching, an omitted expected query permits site-added query metadata only when the origin, pathname, and fragment still match; explicit expected queries remain strict. Stop on a mismatched identity or `AUTH_NOT_PERSISTED`. Inspect the bounded preview immediately, then take a fresh snapshot and prove the site state.
6. Call `browser_frames` before interacting with an embedded application. Select only a frame ID returned by that observation, then pass it as `frameId` to frame-aware tools. Use `frameId: null` for the main document.
7. Continue with snapshots and semantic actions. The currently selected controlled tab remains authoritative while it is live; auxiliary popups and player pages do not silently replace it. Native Chromium also retains a private opaque exact-target identity across compatible worker replacement, so duplicate same-URL tabs are not selected by enumeration order. Its bounded sanitized last-action evidence survives that replacement only when the exact private target, opaque document identity, and sanitized URL still match. Use `browser_tabs` and `browser_select_tab` for deliberate tab changes. If the active page closes and only one page remains, Stage5 selects that sole page automatically. When `browser_snapshot` reports `scope: "modal"`, use the controls and refs from that single active-modal capture. If it warns `ambiguous_visible_modals`, inspect without guessing. If navigation replaces or detaches a frame, discard its old ID and call `browser_frames` again; frame IDs are intentionally session-scoped capabilities.
8. When a snapshot exposes an unnamed element reference, pass both its `snapshotId` and observed `ref` to `browser_click_ref`. A reference is valid only for the latest snapshot of that exact frame and document and is consumed by every attempted action. Stage5 first activates the selected page, then binds the final live target. If React replaces the ARIA ref across that necessary pre-input boundary, Stage5 accepts only one exact role/name-equivalent control inside the retained snapshot modal/document scope; a missing descriptor, changed scope, or multiple in-scope matches fails with definite zero dispatch. If the target is offscreen, Stage5 incrementally moves a visible nested or document scroll surface while retaining the exact DOM node. If a virtualized feed detaches that node, Stage5 accepts a replacement only when the same privacy-fingerprinted article and semantic target are uniquely proven; it never searches the whole page by name. It clicks only when the exact prepared node is visible, enabled, in view, and not covered, using the viewport-and-overflow-clipped visible portion for hit-testing. Immediately before input it observes the controller-selected renderer and records privacy-safe visibility/focus evidence. If the renderer is already visible, Stage5 does not call `bringToFront` or activate the native application. If a controlled Chromium page remains hidden on macOS, Stage5 resolves that target's exact Chromium window, restores it when minimized, explicitly unhides and activates all windows of only the verified Stage5-owned process, reselects the target page, and checks renderer visibility again. If AppKit accepts that request but the already-unhidden owned process remains nonfrontmost, Stage5 may use one remaining-deadline Process Manager request against only the same proven PID before reselecting the page. AppKit acceptance, fallback attempt/resolution/request outcome, hidden state, frontmost state, and renderer visibility are reported separately. A stable-click timeout receives one forced exact-handle attempt only when no trusted event occurred and the target still passes every actionability check. If that handle path also emits zero events, one guarded page-level mouse dispatch may use the clipped visible hit point of the exact main-frame node; the coordinate never leaves the worker. Partial, misdirected, detached, cross-frame, inactive-page, or uncertain dispatch is never repeated. A preparation failure returns `actionDispatched: false`; take a fresh snapshot instead of replaying the consumed ref.
9. When `fileInputs` exposes the intended upload control, pass its `snapshotId`, file-input `ref`, and the explicitly authorized absolute local path(s) to `browser_set_input_files`. The action consumes that snapshot capability, avoids the native picker, and returns a fresh preview. Never replay a timed-out or unconfirmed file selection. `selection.confirmedByInput` proves only that matching privacy-minimized file metadata was observed during the capture-phase input event or in the retained `FileList`; a site may then clear the input after consuming it. `observationMs` accepts 0–5,000 ms for quick sampling. For a known semantic completion/error state, use `completion.timeoutMs` up to 60,000 ms within the overall timeout. Wait for `processing.state: "completion_observed"` or inspect the returned snapshot for a site-specific completion signal before submitting. `unverified` is not success.
10. For a click that is supposed to change state, supply a postcondition such as an expected URL, selected state, or visible element. Selected state includes accessible expanded state, which is the preferred generic check for custom popup openers. Role and ref clicks use the same absolute deadline, exact-target event guard, fallback rules, and evidence-finalization reserve. Trusted-event evidence is retained outside the page document so navigation cannot erase it. Stage5 first proves the selected page visible, using the background-safe no-op when it already is, then binds the final control. Role targets receive a bounded one-second transition wait before `TARGET_NOT_FOUND`; if necessary activation or scrolling replaces a unique role target, Stage5 may resolve it once more only while input is still definitively absent. A fresh ref that React replaces during necessary activation may bind one exact role/name-equivalent target only inside the retained snapshot scope; multiple matches, a replaced scope, or any prior input fail closed. Every native HTML button receives one exact Enter activation instead of a split pointer sequence, including custom-dropdown buttons that omit popup ARIA. Non-native ARIA buttons retain guarded pointer input. The keyboard path never falls through to pointer input, and a partial pointer path is never rebound or replayed. If partial input already produced the requested postcondition, Stage5 returns terminal success with truthful partial dispatch evidence. Otherwise any ambiguous dispatch requires authoritative inspection, never replay.
10a. If a fresh snapshot exposes an unnamed `textbox`/contenteditable ref, use `browser_fill_ref`; do not invent an accessible name or switch to coordinates/focused typing. The snapshot already retains the exact eligible editor and modal/document root as a one-use capability. The fill revalidates that retained frame, document, scope containment, editability and actionability without resolving the ARIA ref or rescanning global modal state. It first inspects the retained editor: if it is already visible and in the viewport, no scroll or native focus change is requested; otherwise Stage5 performs one bounded exact-handle DOM scroll and revalidates it. The ref is consumed once and the supplied value stays out of results and journals. One internal deadline reserves time to return the exact preparation substep plus `target_preparation`, `page_activation`, `fill_dispatch`, `event_verification`, or `value_matching` evidence with target-state and privacy-safe input/change/value-match booleans. A stale or partial fill is inspected, never replayed.
11. Use `browser_scroll` to advance infinite timelines and `browser_find_text` to search what is currently rendered. Stage5 activates the selected page before the baseline and every scroll step; `page_not_active` with false dispatch means no movement occurred, while a failure reporting completed steps means those steps are not replayed. Find-text snippets include the matching rendered line plus a bounded set of nearby unique lines, so inspect that context before requesting a deeper snapshot. If document scrolling does not move and reports nested candidates, take a fresh snapshot and pass the intended `scrollContainers` capability through `target`; never guess a selector. Use `waitFor` with `article_count_growth`, `loading_indicators_disappear`, or `either` when a feed is showing loaders. One exact observation root is pinned for the bounded wait; `scroll_observation_surface_unavailable` means React replaced it, so inspect a fresh snapshot rather than comparing or replaying against the replacement. `scroll_observation_incomplete` means an authoritative semantic limit was reached—or animation-only disappearance could not be proven—so target a smaller fresh surface rather than trusting truncated counts. Loader counts are scoped to that surface's visible region; loading-only status articles remain loaders rather than substantive articles, and unrelated page indicators do not keep the wait open. `targetBoundaryReached: true` is only geometry, calculated with one-CSS-pixel tolerance; `documentBoundaryReached` is true only for the frame document. A downward feed ends only when `endReached: true`, normally through a caller-supplied visible `endMarker`; `dynamic_content_stalled`, a timed-out content wait, and `geometric_boundary_unconfirmed` require inspection rather than a completeness claim. Use diagnostics to inspect the sanitized network activity correlated to the last scroll.
12. After an interaction stalls or fails, call `browser_diagnostics`. Use its sanitized target visibility, enabled-state, viewport, pointer-interception, `dispatchEvidence`, page-error, and request/response classifications to choose the next step. Exact-ref evidence distinguishes selected-page activation/visibility/focus, owned native-window resolution/restoration/activation, handle and page-mouse fallback use, no trusted event, partial exact-target input, a completed click, a blocked misdirection, and a target-state change; never infer safety from a generic timeout or replay a possibly dispatched action.
13. For visual inspection, use `browser_screenshot` and read `captureEvidence`. The selected renderer is verified first; an already-visible page is not unnecessarily foregrounded. If semantic content exists but PNG compression looks suspiciously uniform, Stage5 recaptures once and reports `retryUsed: true`. If the managed image display looks black while the artifact is classified `contentful`, inspect the returned private source `path`; do not treat the client-rendering false negative as page state.

Authentication storage is profile-specific and persistent by design. A session accepted in `profiles/brave` does not authenticate `profiles/chrome`; none of these profiles reuse the user's daily browser profile. The private request/resume bootstrap keeps passwords, passkeys, CAPTCHAs, OTPs, tax identifiers, identity documents, and selfies out of agent control. Chromium-family backends stay in the same native process when control resumes; Firefox waits for exact process exit and actual profile unlock before restarting. On macOS, Firefox's persistent `.parentlock` file is advisory unless `lsof` reports a live holder. The site's visible post-resume UI remains authoritative. See `agent-setup.md` for the full lifecycle.

The pinned Playwright Firefox binary currently reports `navigator.webdriver: true` in a direct native launch even though Stage5 supplies no automation flags. This does not expose the user's private inputs to the agent, but it can matter to bot-sensitive services. Prefer Brave, Chrome, or Edge for login/KYC on those services. Firefox remains supported for native user interaction, exact shutdown/unlock observation, session persistence, and controlled resume; it does not currently promise automation invisibility.

Cross-origin frames use the same semantic action surface as same-origin frames because Playwright owns the browser context. Stage5 Browser does not expose arbitrary JavaScript or CSS selectors as a workaround for inaccessible iframe DOM.

Chromium-engine backends (`chromium`, `chrome`, `brave`, and `edge`) run with Chromium sandboxing explicitly enabled on macOS. Other platforms retain Playwright's platform launch policy until they receive their own verified compatibility coverage. `browser_diagnostics` states the effective safe policy and marks its argument list incomplete rather than exposing a raw command line.

During human authentication, Chromium-engine and Firefox backends run as their native executable with pinned dedicated-profile arguments, a new-window directive, a static Stage5 marker data URL, and the target URL. Chromium also binds one fixed ephemeral control port to `127.0.0.1`; it does not receive `--enable-automation`, `--no-sandbox`, or webdriver-masking code. WebKit has no native human-bootstrap adapter and fails with `AUTH_HANDOFF_UNAVAILABLE`; it does not silently fall back.

## Recovery behavior

After a successful switch, the supervisor records the selected backend. If a later operation wedges the worker, hard recovery starts the same backend and profile rather than falling back to Chromium. A failed preflight leaves the current browser and its tabs running.
