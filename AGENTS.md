# Stage5 Browser agent guide

When this project is checked out inside the Stage5 workspace, read the parent `../AGENTS.md` first. Its rules remain authoritative.

## Product invariant

A browser action may fail, but the controller must never leave the agent or user in an ambiguous state. Every operation must succeed, fail with structured evidence, or complete a defined recovery within a bounded time.

Treat Stage5 Browser as the agent's hand. The model supplies intent and judgment; this runtime supplies perception, reach, controlled force, proprioception, and recovery against unfamiliar interfaces. It must adapt structurally to ordinary website variation instead of requiring a special-case patch or human relay for every new shape. A change that is locally safe but routinely prevents completion of an ordinary authorized workflow is still a product failure.

The product outcome is autonomous browser work, not safety ceremony. Within the user's clearly authorized scope, an agent should be able to inspect unfamiliar sites, exercise reasonable judgment, fill forms, select options, scroll, press buttons, and submit the intended workflow without avoidable human relay. Internal phases, evidence, reservations, and recovery must reduce bottlenecks and remain invisible unless they materially help recovery.

Every mandatory argument, precondition, policy gate, retry prohibition, and human handoff must protect a named product invariant. Remove requirements that merely compensate for an implementation limitation, duplicate evidence already owned by another phase, or force the user to arbitrate an ordinary semantic choice the agent can make within existing authority. Prefer a small composable motion with authoritative effect reconciliation over both broad prohibition and site-specific permission.

Pause for `decision_required` only when semantic ambiguity could materially change the user's outcome, existing authority does not cover the action, or a private-value boundary requires the user. Do not escalate ordinary layout differences, implementation patterns, or low-risk reversible choices that the agent can resolve from observed context. Optional recovery features must never become mandatory round trips for normal browsing.

## Source of truth and bug workflow

- Treat the controlled browser/runtime and its canonical observations as the source of truth. Cached controller state, a dispatched event, an accepted native activation request, a transport response, or a locally predicted transition is never proof of the resulting browser state.
- Do not optimistically toggle, increment, synthesize, or retain user-visible/browser-owned state. Observe the authoritative boundary after a mutation and update controller/shared state from that observation. When the outcome cannot be observed within the bounded evidence reserve, preserve the action evidence and fail closed without replay.
- Start a concrete defect by reading the complete relevant pipeline: tool schema and caller intent -> MCP handler -> supervisor queue/deadline -> worker dispatch -> controller state and browser input -> canonical browser observation -> sanitized result/journal -> caller-visible recovery guidance. Read adjacent invariants and tests before building a reproduction.
- Reproduce first only when the pipeline leaves multiple materially different causes, runtime evidence is required to choose a fix, or the failure depends on unknown environment state. Use a disposable local fixture at the narrowest decisive boundary; never use a live account merely to prove a generic controller defect.
- Implement the smallest coherent root-cause fix for the complete failure class. Convert every reproduced defect into a behavioral regression, then verify the canonical result boundary rather than treating command success as proof.
- Treat durable execution telemetry as privacy-safe audit evidence, never as a substitute for authoritative browser observation. Every supervised browser or recovery operation must be queryable by `operationId` with its stable Lounge agent ID when bound, trace schema and loaded host contract, canonical manager, phase system, dispatch boundary, replay rule, phase transitions when available, reconciliation conclusion, duration, and terminal outcome. Emit transitions from the owning phase manager; do not reconstruct them from an agent narrative. Retain categorical proprioception when it explains a boundary, including target visibility/actionability and viewport proof, popup surface/association proof, rendered-surface count, reach strategy, dispatch evidence, and reconciliation result. When the agent must judge among bounded current candidates, retain the requested-target resolution state, complete active-pool count, exposed count, issued one-use capability count, truncation state, judgment availability, and whether a decision was consumed; never retain candidate semantics. Persist only an explicit allowlist: never display names, providers, command arguments, URLs, selectors, accessible names, field values, page content, query strings, fragments, coordinates, headers, bodies, or private data. Telemetry failure must never replace the operation's canonical result. Trace extraction and journaling run in the long-lived MCP host: any new retained trace field, privacy parser, or host-owned conclusion changes `MCP_HOST_BEHAVIOR_VERSION` and requires fresh-host integration coverage; never advertise it as a compatible worker-only update.

## Module design and ownership

- `AGENTS.md` is the sole canonical engineering guide for this repository. `CLAUDE.md` only points here; do not duplicate rules across agent guides because copied policy inevitably drifts.
- Keep one canonical owner for every mutable lifecycle, selected-page, snapshot-capability, action-diagnostic, handoff, supervisor, and Lounge state. Domain modules receive that owner or an explicit narrow interface; they must not mirror it in parallel caches or infer it from transport state.
- Follow DRY at behavior boundaries. Before adding a locator rule, deadline calculation, activation path, sanitizer, result classifier, state transition, or fixture helper, find and extend the existing canonical implementation. Extract shared behavior when two paths enforce the same invariant; do not create abstractions for merely similar syntax or hypothetical reuse.
- Keep orchestration thin and organize implementation by domain under named folders (for example lifecycle, observation, input, tabs, handoff, diagnostics, supervisor, and Lounge). Imports must make the owning layer clear; avoid circular domain ownership, deep inheritance chains, and catch-all `utils` modules.
- No hand-authored TypeScript source or test file may exceed 1,000 physical lines. Aim for roughly 500 lines or fewer. A file may exceed the target only when splitting it would obscure one cohesive invariant, but it must remain below the hard limit. Generated output, vendored code, and lockfiles are excluded.
- Split tests by behavior and failure boundary, not by arbitrary line ranges. Put reusable fixture construction in focused test-support modules; keep assertions with the behavior they specify.
- Refactors must preserve public schemas, protocol versions, tool counts, fail-closed behavior, and no-replay semantics unless the task explicitly changes that contract. Structural cleanup is not permission to weaken evidence or interaction gates.
- Follow YAGNI. Add a capability, abstraction, compatibility bridge, or configuration only for a current demonstrated workflow or invariant.
- Keep default MCP prose smaller than the task it supports. Server instructions plus public tool titles/descriptions have a hard 584-word ceiling (10% of the recorded 5,846-word legacy baseline); do not repeat lifecycle or safety essays on every tool. Put enforced invariants in code, return contextual recovery only when needed, and keep deeper diagnostics explicitly on demand.
- Lead successful action results with outcome, dispatch state, current state, and one short next-action enum before implementation evidence. Preserve the full privacy-safe evidence after that summary; do not make agents infer ordinary UI state from low-level event fields.
- Never classify human-language intent with regular expressions, keyword lists, or phrase heuristics. Deterministic code may enforce structural browser and protocol facts only.
- Run every consequential browser action through the canonical phases: observe authoritative state -> plan a structural strategy -> preflight invariants -> perform reversible preparation -> enter one dispatch gate -> reconcile authoritative effects -> finalize sanitized state and persistence. One bounded recovery may return from dispatch to preflight only after exact evidence proves zero input; possible input proceeds only to reconciliation and must never be replayed.
- Be positional. Before applying input, establish the smallest controllable state that limits what the page can do next: one exact owned target, one bounded reach strategy, one dispatch boundary, and one authoritative effect to reconcile. Prefer changing position through safe observation, scrolling, focus, or popup ownership over enumerating site-specific moves. A wider motion vocabulary is useful only when every alternative preserves the same certainty and no-replay boundary.
- Make viable moves visible. At each phase boundary, expose every currently available generic technique that can materially advance the authorized goal, not only one `suggestedAction`. Describe each alternative through a stable technique ID, its structural prerequisites, expected effect class, preparation/dispatch cost, authority or private-handoff requirement, and replay consequence. Keep this affordance view bounded and privacy-safe; never include page text, selector details, entered values, or inferred business meaning. The agent chooses the semantic tactic from observed context and user scope, while deterministic managers decide only whether each motion is structurally available and how its effect can be proven. Do not turn a preferred tactic into a mandatory path when another composable safe motion is viable.
- Compress perception structurally before applying text filters. Prefer the active modal or popup, requested control, nearest owning field, current options, validation errors, and stable action refs; summarize unrelated regions with explicit omitted counts so absence is never inferred. Offer task views such as active surface, form, control, and full page over one canonical observation model. Regex or literal matching may narrow text only inside an already proven scope; it must never decide semantic importance, ownership, user intent, or which action to dispatch.
- Assign every public browser motion to one manager and one declared phase system in the canonical command/tool contracts. A manager may share generic techniques, but no action family may be unowned, bypass the dispatch gate, or invent a parallel lifecycle. When a dogfood workflow exposes a missing motion, extend the smallest generic manager primitive and its acceptance matrix rather than adding a site-specific escape hatch.
- Treat a command-contract technique as a tactic the caller can deliberately choose through the public operation or its parameters. Keep automatic backend mechanics, reconciliation substeps, and internal phase transitions in the owning manager, but do not emit them as duplicate available moves that compete for the bounded affordance budget.
- Keep one explicit host/controller context per scoped runtime. A stable Lounge identity durably scopes only its selected Stage5 browser backend and explicit review-policy mode so a host reconnect cannot silently fall back to another profile; different agents never share a global last-browser value. Browser objects, handles, one-use refs, URLs, pages, live visibility, and dispatch probes are ephemeral and must be re-observed. Only that minimal agent context, sanitized operation outcomes, ownership/handoff identity, update state, and Lounge coordination cross a durability boundary through their canonical narrow stores.
- Keep agent identity, browser-profile ownership, and external human/account authority distinct. A stable Lounge agent ID identifies the tool caller, not the person or account signed in to a service; several authorized users may legitimately use different accounts or consoles. Before an account-scoped mutation, verify the intended user/account/organization through an authorized privacy-safe surface and bind it to the current task scope. Never inherit authority from another user's open xAI, financial, social, or administrative console, and never persist account content merely to distinguish users.
- Deterministic planning may return a typed, privacy-safe `decision_required` checkpoint when structural facts are insufficient to choose the user's intended meaning. Let the agent exercise judgment only within existing user authority, and escalate consequential or materially ambiguous choices to Mikey. After a choice, re-observe and bind one exact target before dispatch. Do not encode business meaning in selectors, regexes, scoring heuristics, or site-specific core patches.
- Apply that judgment boundary across every manager, not only forms. Deterministic code owns current identity, connectivity, visibility, containment, actionability, freshness, control mode, authority requirements, dispatch evidence, deadlines, and resulting state. The agent owns semantic equivalence, tactic selection, and user-intent interpretation from bounded observed alternatives. When an algorithm cannot establish meaning without a heuristic guess, return the smallest current candidate set and an explicit auditable agent-decision input; never let that input override a stale capability, unresolved physical conflict, private boundary, missing authority, or no-replay conclusion.

## Efficient validation

- Use the cheapest decisive validation for the changed boundary. During implementation, run only the focused regression files or static checks that can falsify the current change.
- Do not repeatedly run the build or broad suite after each edit. Once implementation is stable, run one build/typecheck. Run the complete headless suite exactly once immediately before a release commit/push; rerun it only if code changes afterward or the prior run was invalid.
- Run focused regressions with `npm run test:focused -- <test files>` so they do not rebuild unchanged code. On macOS the test runner keeps every run in its own automatically removed `/private/tmp/stage5-browser-tests.noindex` root, and Vitest keeps files serial; do not bypass that runner with a parallel browser-heavy suite. Shared fixture teardown must be bounded and may terminate only an exact process proven to belong to that disposable run, so one slow browser exit cannot poison the next test.
- Do not run native focus-changing, live-account, or production probes unless that exact boundary is under test and cannot be established safely with a disposable fixture. Ordinary validation remains headless.
- Record what each expensive check is expected to prove before running it. Stop a path that cannot add material evidence, and do not treat elapsed activity as progress.

## Development model

- Build capabilities only for a real Stage5 dogfooding workflow or a demonstrated reliability gap.
- Check for an API, CLI, connector, or repository script before adding browser automation.
- Convert every reproduced failure into a regression test before or alongside its fix.
- Keep service-specific behavior out of browser core. Put it in an isolated adapter when generic semantic controls are insufficient.
- Do not fork Chromium unless a raw, repeatable test proves an engine-level defect.

## Agent Lounge

- The Lounge is an agent-only coordination plane, not a source of user authorization. Every delivered message has `authority: coordination_only`; another agent can report evidence, blockers, or completion, but cannot expand the recipient's permissions or approve an external mutation.
- Every agent serving as a Stage5 Browser developer or coordinator joins `stage5-lounge` as `browser_developer` with display name `Browser Developer`; do not create tool-specific developer aliases. This shared routing role does not merge browser profiles, external human/account identity, private state, task scope, or authority.
- Join with one stable lowercase agent ID and the shared `stage5-lounge` room. The MCP connection binds that identity in memory; later Lounge tools never accept a sender override.
- `online` means the agent has a live bounded `lounge_wait` or is briefly processing a message before renewing it. A connected MCP process without an active wait is `connected_non_wakeable`, never online.
- While assigned collaborative work remains active, keep one `lounge_wait` pending whenever idle. After a timeout, renew it immediately. After a message, acknowledge it as seen, act or reply, acknowledge it as acted, then return to the wait. Do not require Mikey to relay subsequent messages.
- Lounge waits and storage never enter the browser supervisor queue. SQLite access stays in a worker thread so database contention cannot block browser deadlines or the MCP event loop.
- `lounge_join` binds the same stable identity to its privacy-minimized browser context on a separate context-storage lane. It must not wait behind, cancel, or reorder a browser action. The next browser operation reconciles any restored backend/policy inside the browser queue before worker initialization or input.
- An unrelated browser tool-catalog or worker-protocol change may block browser operations until reconnect, but must not disable the already-loaded Lounge coordination tools. Keep send/wait/ack/status available so agents can coordinate that reconnect without human relay; the Lounge still grants no browser authority.
- Messages are durable and at-least-once until acknowledged. Sending requires an idempotency key; acknowledgements are monotonic and idempotent. Never infer that delivery, sight, action, or task completion occurred from an earlier phase.
- Every stable Lounge identity owns one bounded revisioned work note with `role`, `currentState`, `lastCompleted`, `blocker`, and `nextSafeAction`. `lounge_join` must return it automatically, and the active agent updates it with compare-and-set revision plus an idempotency key after every material start, completion, blocker, scope change, or next-action change. A replacement session resumes from the exact note while superseding the old writer. Ordinary agents can read only their own note; a locally trusted manager may read all current member notes through status. Notes are coordination-only context, never permission or a browser-operation gate, and must follow the Lounge privacy rules.
- Never send passwords, OTPs, cookies, API keys, tax identifiers, payment details, private addresses, identity documents, form values, or chain-of-thought through the Lounge. Share only the minimum conclusion, evidence identifiers, repository artifacts, and next action needed.

## Reliability rules

- The MCP process supervises a separate browser worker. Do not move browser ownership into the MCP event loop.
- All browser commands pass through one serialized queue and have an outer hard deadline.
- A hung worker must be terminated with the browser process group it owns before replacement.
- Every persistent-profile launch must first claim the private atomic Stage5 ownership lease. Heartbeat the exact worker start identity, exact browser start identity, canonical executable fingerprint, control mode, and release phase. Classify another live lease as `busy_other_stage5_session`; recover an orphan only after every identity check still matches. Never overwrite an invalid lease, delete browser locks, or signal an unknown process.
- Never retry a consequential operation after an ambiguous timeout. Verify authoritative state first.
- Navigation uses commit-first semantics with a separately bounded readiness probe.
- Do not return an arbitrary first match for an ambiguous locator.
- Treat a semantic snapshot's `snapshotId` and refs as document-bound capabilities. Never accept a ref that was not present in the latest snapshot of the same frame, and invalidate every ref after navigation or an attempted action. A React replacement caused only by necessary pre-input page activation may be rebound once while dispatch is definitively false, but only to one exact role/name match inside the retained snapshot modal/document scope; missing semantics, scope replacement, or multiple in-scope matches fail closed.
- Include a snapshot-observed direct link destination in the identity of an unnamed ref. Exact-ref activation and virtualization recovery must reject a same-role/name link with a different destination; the destination remains worker-internal and is never returned in diagnostics beyond the snapshot's existing sanitized semantic output.
- Suppress popup option/surface subtrees that are CSS-visible but outside the viewport or clipped out of it. Do not expose an offscreen popup-backed scroll container as a capability, and do not let an offscreen popup option satisfy `expectedVisible`. Preserve ordinary offscreen page refs so bounded exact-node scrolling remains available.
- Fill unnamed non-private textboxes and contenteditables only through a fresh `browser_fill_ref` capability. Reject password inputs and keep all private-value fields in the private handoff. During the semantic snapshot, retain the exact eligible editor handle and exact modal/document root handle for every exposed fill capability. At fill time, use only those one-use handles: never re-resolve the ARIA ref or rescan the page for the current modal. Revalidate the exact document, frame, retained scope containment, editability, visibility, and enabled state. Inspect the retained editor before viewport preparation and skip movement when it is already visible and in view; otherwise use one short bounded exact-handle DOM scroll followed by revalidation, never Playwright's stability-gated scroll. Use one deadline with a result-finalization reserve; consume the ref on every attempt; retain the exact preparation substep, structured fill phase, target state, input/change, and exact logical value-match booleans; never log or return the supplied value.
- Treat hidden file inputs as a distinct one-use snapshot capability. Accept only explicit absolute paths to readable regular files; reject symlinks, directories, stale refs, disabled inputs, and unsupported multiple selection before dispatch. Never log or return absolute paths, and never open the native picker.
- When a click is intended to change state, use a bounded postcondition. Treat popup/select/menu openers as state-changing even when they seem reversible: a native keyboard activation can detach after a trusted keydown but before its click, and only the caller's requested visible/selected/hidden state can reconcile that partial input. Never send an opener click with a null postcondition when a privacy-safe semantic effect is available. If a postcondition fails, report that input was dispatched and never replay it without a fresh observation.
- Use `expectedHidden` only for an exact semantic role/name whose absence from the visible semantic surface is a sufficient privacy-safe effect boundary. Zero exact matches or a bounded set in which every exact match is hidden passes; any visible match fails. A candidate set above the explicit bound, a missing frame, or an observation error remains unknown and fail-closed. Results expose only the expected/observed visibility booleans, never the semantic name. Combine that effect with exact-target dispatch evidence; do not claim a persisted field value or downstream submission that the hidden-state boundary cannot prove.
- If partial or ambiguous exact-target input has already occurred, reconcile any supplied postcondition within the reserved finalization budget. An observed requested effect is terminal success with the original partial dispatch evidence; an unobserved effect remains non-retriable and must never be relabeled as definite no-dispatch.
- Distinguish controller state from profile ownership. `browser_status.state: stopped` does not mean a profile is free when `profileLockState` is `possible_external_owner`. Allow the bounded owned-release path; never remove a lock or kill an unknown owner.
- Before clicking a fresh observed ref that is outside the viewport, use bounded incremental movement on a visible nested or document scroll surface while retaining the exact DOM node. If virtualization detaches it, rebind only when the same privacy-fingerprinted article and the same semantic target are each unique; never fall back to a global name match. Revalidate attachment, visibility, enabled state, viewport intersection, and pointer interception. Consume the snapshot on every attempted ref click. If viewport preparation fails, return immediately with `actionDispatched: false`; do not enter the ambiguous click path.
- Route role and ref clicks through one exact-target engine with one absolute action deadline and a reserved evidence-finalization window before the supervisor deadline. Establish and verify the controller-selected page's visibility before binding the final live click target, then verify it again immediately before input. A unique role target may be resolved again after necessary page activation only while dispatch remains definitively false. A fresh ref whose ARIA ref disappears across that same activation boundary may be rebound once only through its snapshot-captured exact role/name inside its retained modal/document scope; never use a global name-only match, accept multiple in-scope candidates, or rebind after any input. If the final read-only guard observes that the selected renderer became hidden after target preparation, one recovery cycle is allowed only when exact evidence proves both action and click dispatch false: discard the prepared handle, activate and settle the page, then repeat the same bounded final target resolution before the one input attempt. A second activation loss, missing/replaced scope, target ambiguity, deadline exhaustion, or any trusted event fails closed without another cycle. Already-visible pages take the background-safe no-op path. If a controlled Chromium page remains browser-hidden on macOS, resolve its exact target window, restore it when minimized, explicitly unhide and activate all windows of only the verified Stage5-owned process, then reselect the target and re-check renderer visibility; never select a process by name/title or expose its PID/window ID/geometry. AppKit accepting an activation request is not proof of foreground state: report accepted-request, hidden/unhidden, frontmost, and final renderer-visibility facts separately. If AppKit leaves an already-unhidden exact owned process non-frontmost, one bounded Process Manager fallback may target that same proven PID within the remaining activation deadline; it must not claim direct user activity, select by bundle/name/title, or bypass the final renderer-visibility gate. Retain privacy-safe event evidence outside the document so a successful navigation cannot erase its trusted click proof. A normal stable-click timeout may use one guarded forced exact-handle attempt only when the first attempt emitted no trusted event and the same node remains fully actionable. If both handle paths emit zero events, one page-level mouse dispatch may target the exact fresh main-frame hit point while the same guard remains live. Block events that miss the exact node or reach it after its state changes. Return clicked, definitely not dispatched, or ambiguous evidence before the outer deadline; never fall back after partial input, unavailable evidence, detachment, cross-frame ambiguity, or failed page activation; never expose or journal coordinates.
- Prefer background-safe control: when the controller-selected renderer is already visible, do not call `bringToFront` or activate the native application. Escalate to exact-page and exact-owned-process foreground recovery only when renderer visibility proves it is necessary.
- Compute click actionability and fallback hit points through the canonical exact-target geometry evaluator. Begin with the target's viewport-and-overflow-clipped visible region, not its raw bounding-box center. CSS overflow ancestry is an inference, not browser paint truth: when it collapses the region, override it only if a bounded `elementFromPoint` probe inside the target's own viewport-clipped client rectangles hits that exact target or its proven composed-tree descendant. A non-target hit never makes the target in-view. Prefer the proven center, then a fixed bounded alternate grid, following assigned slots and shadow hosts to match trusted event paths; retain only categorical viewport evidence plus the center/alternate fact and never expose coordinates. If bounded scrolling makes the exact retained target geometrically visible but a sibling still covers every candidate point, continue reversible preparation by moving that same target toward the nearest scroll surface's interior and re-run exact hit testing; stop without input when no bounded movement can establish contact. Use the same freshly recomputed exact position for handle input and repeat the exact-hit override in the synchronous pre-input guard. Unrelated siblings, ancestors, overlays, detached replacements, and fully covered targets outside the exact composed path remain blocked for pointer dispatch. A fully pointer-covered native HTML button may proceed only through its preselected guarded keyboard transport when the caller supplied a non-null bounded postcondition; it must remain attached, visible, enabled, in the viewport, and controller-selected, and it still requires exact trusted-event evidence plus postcondition reconciliation without replay.
- A unique role target may be resolved once more after pre-input activation or scrolling replaces it, but only while dispatch is definitively false. Ordinary native buttons and button-shaped options use one exact guarded pointer transport; never let framework focus or an active-first keyboard handler substitute another option for the observed target. A native button may use one preselected guarded keyboard transport only when the caller supplied a non-null bounded postcondition: Enter is the default, while an explicitly expected visible menu/list option role selects Space before input. Record exact-target trusted keydown/keyup and pointer/mouse/click evidence. A transport returning is not proof that input reached the target, and a target detaching after any trusted event is possible input that must be reconciled without replay. Never change keys or transports after input, rebind after input, or suggest replay when dispatch is partial or ambiguous.
- Treat `browser_inspect_control(revealOptions=true)` as a reversible-view action, not a pure read. Discover popup surfaces through one bounded source of truth: semantic list/menu/tree surfaces first, plus rendered option groups only when a positioned/popover/dialog overlay ancestor proves a portal boundary. Retain the innermost real scroll surface when one exists. When one broad positioned portal contains strict option branches separated by a real bounded visual gap, partition those branches before ownership; contiguous option wrappers remain one surface. Prove popup ownership in this order: explicit/structural relation, unique focused owner, unique expanded owner, then spatial ownership. Within a non-structural proof tier, several plausible owners may resolve only when one has a decisive normalized edge-gap lead; an exact/near tie remains zero-input ambiguity. In the weakest spatial tier only, a materially overlapping sibling proven covered by the popup's own hit-test path cannot defeat one tightly adjacent exterior anchor; structural, focused, expanded, uncovered-overlap, and true exterior conflicts still fail or retain their stronger priority. Never let a merely focused, expanded, or nearby target claim a popup with a different structural owner. Treat DOM wrappers and split panels as layout, not semantic ambiguity: nested surfaces collapse to their outer owned root, while disjoint surfaces are one bounded composite capability only when every retained surface proves the same exact control owner. Different owners remain a zero-input ambiguity. If reversible preparation authoritatively proved zero rendered popup surfaces, the exact opener then possibly received input, and reconciliation finds exactly one newly rendered bounded surface, associate that surface as `post_dispatch_unique` causal evidence even when passive spatial owner candidates tie; this inference is unavailable before input, when any surface was already rendered, or when more than one new surface appears. If opener input is partial, reconcile the exact owned surface set and continue from that state without replay. If the intended popup set is already proven open, inspect it without closing or reopening it even when another popup is also visible. Return and journal only categorical surface/association/ownership proof and bounded counts—never geometry, names, options, or page content.
- Reconcile custom option state against the exact retained option, control, popup, and smallest adaptively isolated field region. A multi-select popup may intentionally remain open; popup closure is neither required nor sufficient proof that one of its options became selected or unselected. Require authoritative option state or an exact representation appearing/disappearing inside that field region, exclude the owned popup and competing fields, and treat unavailable state as unknown. An unselect motion requires positive current-selection evidence so a toggle cannot move in the wrong direction. Bounds constrain time, dispatch count, evidence retention, and privacy—not valid DOM depth, option count, or widget layout.
- A missing role target is a pre-dispatch result. Wait only through the bounded transition window, then return explicit false dispatch evidence and require a fresh snapshot; never attribute an earlier or autonomous UI change to a `TARGET_NOT_FOUND` operation.
- File selection is consequential. Confirm privacy-minimized name/size metadata during the capture-phase input event or from the retained browser `FileList`; sites may consume and clear the input synchronously. Return a fresh semantic preview, and report processing as completion observed, in progress, error observed, or unverified. Temporal network activity is evidence, not proof of upload completion; never replay an ambiguous selection.
- Keep the agent-selected controlled tab stable while it remains live. A transient popup or auxiliary player page must not silently steal the active-page pointer. If the selected page disappears and exactly one live page remains, reconcile to that sole page so `activePageIndex` cannot remain null.
- Expose duplicate tabs only through session-scoped random opaque capabilities returned by `browser_tabs`. Select by that exact capability and never fall back to URL, title, enumeration order, or a stale positional index. Background-tab inspection is passive by default, strips every action ref, and reports when a modal can suppress underlying accessibility content. When no modal is visible, append at most three novel visible outermost article/standalone-quotation detail captures at depth 20, bounded to 30,000 characters total and stripped of every ref; never retain handles or turn the detail into an action surface. Explicit temporary renderer activation may pin the target and prior controller selection, use only bounded generic loading/content evidence, avoid native application activation, and recover the same exact renderer once if visibility is lost during that wait. A second loss, failed recovery, or hidden capture boundary fails without element input. Always restore the exact prior selected renderer in `finally`, and return only after restoration is proven.
- Preserve an opaque exact Chromium target identity in the private native-control record so compatible worker replacement cannot select a duplicate same-URL tab. During a graceful controlled-native worker handoff, retain only the bounded privacy-safe last-action diagnostic together with that exact target and its opaque main-document identity; restore it only when all identities and the sanitized URL still match. Never return or journal either opaque identifier, and never let retention alter an action result.
- Return structured warnings for non-2xx navigation responses and explicit redirect evidence; a committed response is not automatically a successful workflow result.
- Keep scrolling and text search bounded and generic. Do not add arbitrary agent-supplied JavaScript or service-specific timeline code.
- Keep `browser_find_text` useful on noisy social feeds by returning a bounded window of nearby unique rendered lines around each match. Preserve original rendered line numbers, suppress repeated context generically, and never expand this into an unbounded page or article dump.
- Treat observed nested scroll containers as distinct one-use snapshot capabilities. Never accept a container ref from another snapshot/frame/document, guess a selector, or silently choose among candidates.
- Separate geometric scroll boundaries from semantic feed ends. Use a one-CSS-pixel tolerance for browser geometry. A downward boundary without an explicit visible end marker is unconfirmed; unresolved loading or an unmet bounded content wait plus no movement is a stalled feed, not a completed timeline.
- Before collecting a scroll baseline and immediately before every scroll step, activate the controller-selected page and require its renderer to be visible. Fail closed with definite false dispatch when the first activation fails. If visibility is lost after completed steps, report their exact count and never replay them.
- Pin one content-observation root for the entire scroll operation: the exact nested target, one uniquely visible semantic `[role="feed"]`, or the current viewport. Never rediscover a different root between before/after samples. If the pinned root detaches, return prompt structured surface-loss plus completed-step/dispatch evidence; never interpret it as loader disappearance, wait out an impossible reconnection, or replay movement. Count loading indicators only within that surface's visible portion. Treat an explicitly loading status outside a content unit, or statuses that are the sole substantive content of an article/standalone-quotation shell, as unresolved loading evidence; exclude that shell from growth. A visible leaf whose complete rendered text is exactly a generic loading phrase may count only through a bounded text scan, and its disappearance is proof only when that scan remained complete. Prefer explicit semantic loaders and skip the text scan when they exist. Count outermost standalone `blockquote` roots as article-shaped content without double-counting quotations nested inside articles or other quotations. Unrelated offscreen, out-of-surface, or statuses inside otherwise substantive posts must not hold a content wait open. If a bounded authoritative semantic scan reaches its internal candidate limit, fail closed as incomplete observation; never infer growth or loader disappearance from truncated counts. Track the optional animation heuristic separately so its cap cannot block semantic content growth or explicit loader disappearance, and never infer animation-only disappearance from an incomplete heuristic scan.
- Journal scroll as the current sanitized page action so diagnostics can isolate its bounded network activity. Expose only action state, aggregate content counts, scroll geometry, and sanitized request classifications—not selectors, classes, page text, or raw network data.
- Prefer one ARIA capture rooted at a uniquely established visible modal over stitching multiple snapshots or globally increasing document depth. Preserve one valid ref map; warn and fail back to the document when modal choice is ambiguous.
- Page and click diagnostics must be bounded and sanitized. Expose categories, counts, status, and actionability facts—not raw console/exception text, request bodies or headers, query strings, fragments, entered values, or a full browser command line.

## Private interaction handoff

- Isolated persistent profiles remain the default security boundary. Do not attach to or copy cookies from a person's everyday browser profile.
- Agents call `browser_auth_status` before account-dependent work. The tool reports lifecycle state, not a guessed authenticated boolean.
- Before a private password, passkey, CAPTCHA, OTP, EIN, identity-document, selfie, or KYC step, explicitly select the intended backend; concurrent agents may legitimately have different Stage5 Brave, Chrome, Chromium, Edge, or Firefox windows. The workflow is `browser_request_login_handoff` → user acts privately in the exact native application named by the result, using its Stage5 identity-marker tab and short handoff label to distinguish it → user follows the returned backend-specific instruction → `browser_resume_after_login` → returned bounded preview → fresh full semantic snapshot. Do not claim tab-strip adjacency that the browser does not expose authoritatively. Chromium-family browsers stay open for same-process attachment; Firefox exits normally for restart-based resume. Private values and documents never pass through agent arguments, messages, or logs.
- The human bootstrap uses the same isolated profile and launches the selected browser without Playwright automation flags. Chromium uses a fixed ephemeral loopback-only CDP endpoint so Stage5 can attach only after the user finishes, without restarting the authenticated browser; the endpoint remains private and is never returned to an agent. Do not replace this with stealth flags or script-based `navigator.webdriver` overrides.
- If the initial request returns `releasing_control`, call `browser_request_login_handoff` again with the same operation intent. It resumes the retained `close_requested → process_exited → profile_unlocked` phase and must not relaunch the controlled browser or repeat the private step. While state is `awaiting_user`, do not call tab, page, action, start, switch, recover, or stop tools. Stage5 Browser intentionally refuses control while the human window owns the profile.
- A compatible completed build is deferred while the human window owns the profile. Resume through the already-running worker first; the supervisor rolls forward before the following operation.
- Build fingerprints identify exact artifacts; they are diagnostic evidence, not compatibility contracts. A fingerprint-only mismatch must never produce `MCP_RESTART_REQUIRED`. If a compatible build appears while a private handoff is active and the old worker exits, adopt the completed fingerprint before replacement. New workers retain a one-operation initialization bridge for already-running legacy hosts that enforced fingerprint equality, then normalize to the true loaded identity after the handoff completes.
- Never force-close the private browser or delete profile locks. For Chromium, ask the user to leave the dedicated instance open and resume into that same process. For Firefox, ask the user to quit normally; model shutdown as close requested, exact process exited, then profile unlocked, using the remaining operation budget. On macOS, `.parentlock` existence alone is not ownership—confirm whether the OS reports an active holder. If Firefox's process exit is abnormal or unavailable after the process is gone and locks are clear, do not repeat the private step: the first resume offers a bounded explicit override, and one deliberate second resume uses it. Never rewrite browser exit preferences.
- Do not infer `navigator.webdriver: false` from the absence of automation flags. The pinned Playwright Firefox runtime currently advertises WebDriver even in its uncontrolled native process. Prefer Brave, Chrome, or Edge for bot-sensitive login/KYC handoffs; Firefox remains supported for the shutdown/unlock/session-resume lifecycle, and this limitation must stay explicit until an unmodified controllable Firefox backend exists.
- The uncontrolled phase cannot observe exact manual clicks or network traffic. Treat `lastHandoffOutcome` as a sanitized before/after boundary comparison, then use a fresh snapshot to verify account state.
- Treat the returned executable, application name, user-data directory, profile directory, and effective profile path as one binding. Resume must fail as `AUTH_NOT_PERSISTED` when that binding changes, or when the human phase added target-origin session metadata but reattachment cannot reach a caller-supplied non-root post-login route. Cookie values are never inspected. Do not infer live cookie absence from an open Chromium SQLite database; the browser may hold a valid in-memory jar while migrating stores. Storage continuity is still not proof of authentication; stop if the bounded preview or fresh snapshot shows signed-out controls.
- On Chromium resume, inspect `runtimeProfile` and all three storage observations: `afterHumanBrowser`, `afterControlledStart`, and `afterTargetLoad`. Report `lossBoundary`, `automationCorrelation`, `targetOriginLoadedAtControlledStart`, and the visible site state. `playwright_start` points to launch/profile/storage-policy investigation. `target_load` with `loss_after_automation_exposure` justifies designing an extension-control path only after repeated evidence; it does not by itself prove `navigator.webdriver` caused invalidation. `preserved` plus signed-out UI means the site rejected or expired state that key-only metadata cannot identify. Never inspect or expose cookie values.
- Do not use an origin-only URL as an authentication postcondition. Use a non-root post-login route when one is stable, or omit the URL expectation and verify the preview plus a fresh snapshot. For an exact authentication route with no expected query, Stage5 accepts site-added query metadata only when origin, pathname, and fragment still match; an explicitly expected query remains strict. This authentication-only rule must not weaken generic navigation or click URL postconditions.
- A successful login persists per selected backend profile. It does not transfer between Brave, Chrome, Chromium, Edge, Firefox, or WebKit.

## Host connection and update lifecycle

Before browser work, distinguish a missing host connection from a failed browser runtime:

1. Confirm the current agent exposes the `stage5_browser` tools. Read the expected count from `package.json` at `stage5Browser.toolCount`; do not rely on a remembered release number.
2. If the tools are absent in ChatGPT, run `codex mcp list`. The expected entry is `stage5_browser`, enabled, pointing directly to this repository's `dist/launcher.js`.
3. If the CLI entry is enabled but ChatGPT does not expose the tools or show the server, the running ChatGPT host predates the registration. Fully quit and reopen ChatGPT once, then start or resume an agent run. Do not rebuild, redeploy, reinstall, or rewrite the registration.
4. When the tools are present, call `browser_status`. A normal build reports the version and tool count declared in `package.json`, plus `restartRequired: false`.
5. `compatibleUpdateAvailable: true` is not a blocker. The next browser operation automatically rolls the worker onto the compatible completed build.
6. Reconnect the MCP host only when `restartRequired: true`. That flag is reserved for a real tool-catalog, MCP-to-worker protocol, or MCP-host lifecycle-behavior change; exact build-fingerprint drift alone is never sufficient.

Do not kill an observed MCP or worker PID merely because it is old; other active agent sessions may own it. Do not use `browser_recover` as an update mechanism. After a launch failure, call `browser_diagnostics` and follow its structured action.

When changing Stage5 Browser itself:

- Worker-only behavior fixes keep the existing tool-catalog, worker-protocol, and host-behavior versions. `npm run build` publishes a completed build stamp last, and live hosts pick up the compatible worker automatically.
- Never close and reconstruct a connected direct-Playwright context merely to load a compatible update; defer until explicit stop. A proven native-CDP process may roll forward in place because the browser remains running and its exact selected target is retained.
- Adding, removing, or changing an MCP tool schema requires a tool-catalog version bump.
- Changing the MCP-to-worker command contract requires a worker-protocol version bump.
- Changing lifecycle behavior implemented by the already-running MCP host requires a host-behavior version bump. When introducing a new host-version field that an older host cannot read, also change a contract version that the older monitor already understands so it fails closed and requests one reconnect.
- Keep the contract metadata in `package.json`, constants in `src/runtime-info.ts`, package/plugin versions, and regression tests aligned.
- Never tell the user to patch or deploy this local integration. The registered launcher reads this checkout directly.

See `docs/agent-setup.md` for host-specific checks and the exact decision tree.

## Security and privacy

- Never automate the default Chrome profile. Use the dedicated Stage5 Browser profile or a temporary test profile.
- Do not add arbitrary JavaScript evaluation, credential extraction, CAPTCHA bypass, or unrestricted file navigation.
- Do not log command arguments, page content, form values, cookies, headers, query strings, fragments, screenshots, credentials, or OTPs.
- Enable Chromium sandboxing on macOS unless a documented, reproduced browser incompatibility requires a narrower exception. Do not expose raw launch arguments; diagnostics may list only known security-relevant policy facts.
- Screenshots are explicit operations, stored outside the repository with restrictive permissions.
- Activate the selected page before screenshots. Return privacy-safe artifact evidence and one bounded recapture for a possibly uniform artifact with semantic content. If a managed client shows black while the artifact is classified contentful, inspect the returned source path rather than declaring the page blank.
- Browser tools that may change external state must be marked as writes in MCP annotations.
- Keep the ordinary build and test suite headless. A native window-activation smoke proves real macOS foreground recovery and therefore necessarily interrupts the user's active application/Space. Enable `STAGE5_BROWSER_ALLOW_FOCUS_CHANGE=1` only when native foreground behavior is the boundary under test; disclose the expected interruption, but do not turn this narrow technical opt-in into a repetitive approval gate. Do not treat that smoke as routine validation for changes outside native activation.
